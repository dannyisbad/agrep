# Architecture

The reference for agrep's module structure: what is enforced today, and by
which mechanism. The rule this file lives by is that a claim about structure
names the test that enforces it, or says plainly that nothing does yet.

## The layer model

Imports normally point downward or sideways. One upward edge, `recall→search`,
is allowlisted and described under known exceptions below. The authoritative
module→layer table lives in `py/test_layering.py`. It is not duplicated here,
so it cannot drift from here. The test AST-walks every import (lazy
function-level included), fails any module missing from its table (adding a
module forces a placement decision), and runs a two-way ratchet: a new upward
edge fails, and an `ALLOWED_UPWARD` row whose edge no longer exists also fails,
so fixed debt cannot silently return and the allowlist can only shrink. The
allowlist fell from four rows to one.

## Standing structure, with its enforcing mechanism

- **Adapter truth**: `py/hookless/agent_registry.json`, `include_str!`-pinned
  into Rust at compile time, import-fatal `require_exact` validation in
  Python, and `py/test_agent_store_contract.py` driving the real release
  binary against fixture stores. Adapter lists derive from that registry, with
  one exception: `py/archive.py` keeps its own hand-maintained `ROOTS` table of
  store globs, checked only by an entry-count assertion in `selftest.py`. A new
  hand-written list anywhere else is a review-blocking defect.
- **Claims**: `py/ownerfile.py` is the one primitive: post-create re-read by
  default, tombstoned exact removal; owner classification is
  `ownerfile.classify_process`. `py/test_coordination_contract.py` fails any
  Python `O_EXCL` outside ownerfile. The Rust-shared `IndexLock` delegates its
  Python file operations to ownerfile; Rust `create_new` remains separately
  pinned in `crates/agrep-cli/src/index_lock.rs`.
  `docs/COORDINATION.md` indexes every coordination record.
- **Output vocabulary**: `py/surface_policy.py` with `assertIs` identity
  pinning; governor narration is generated by the deciding function, so
  prose cannot contradict the blocker.
- **Embedding lane identity**: two engines write vectors (ONNX int8 on CPU,
  MLX fp16 on Metal via `py/mlx_embed.py` and `py/mlx_modernbert.py`), so the
  lane is part of the stored manifest identity rather than a runtime detail.
  `embedder.profile_string` suffixes only the Metal lane, which leaves every
  pre-lane store byte-valid and re-embeds nothing; `resolve_lane` conforms to
  the lane already on disk instead of re-deciding per process; and
  `_start_metal_lane` refuses to open below a 0.995 cosine floor against the
  ONNX vectors for a fixed short-and-long probe set, because a pooling
  mismatch scores about 0.77 while shared-weight arithmetic drift measured
  0.99875. Pinned in `py/test_mlx_embed.py`. See `py/README.md` for the
  operational contract.
- **Semantic process split**: the meaning lane is three processes, not one
  module, and the split is deliberate: a one-shot agent command must not pay
  model startup per query, and the freshness daemon must not hold native
  runtime memory forever. The calling process runs the query engine
  (`py/semantic.py`); one resident worker (`py/semworker.py`) is the single
  serialized model owner, reached over authenticated loopback, and exits after
  an adaptive idle lease so native RSS is actually returned; one background
  embedder (`py/embed.py`) publishes vectors, at most one per data dir. Each
  holds its own claim through `py/ownerfile.py`, and every record — the worker
  owner, the embed claim, the compaction claim, the publication namespaces — is
  tabled in `docs/COORDINATION.md` with its reclaim policy. The worker's records
  live in a private per-user runtime namespace keyed to a digest of the data
  dir, which binds a worker to one corpus without granting sandboxed readers
  corpus-write authority. Ownership, start-claim races, contention, and teardown
  are pinned in `py/test_semworker_owner.py`, `py/test_semworker_start_claim.py`,
  `py/test_semworker_contention.py`, and `py/test_semworker_teardown.py`.
  A transport failure after a request is sent is terminal for that attempt:
  the caller falls back to keyword rather than stacking a second in-process
  inference.
- **Teaching surface**: the taught block text lives in `py/nudge_default.md`
  and `py/nudge_codex.md`, not in `py/teach.py`. Selftest hash-pins the default
  block against its version number, so changing that file without bumping the
  version fails; it also asserts both blocks still name every command they
  route to. The demo-line byte-compare against live probe output binds only
  when a block carries a demo line, and the current lean blocks carry none, so
  the codex block's text is asserted by route coverage rather than by hash.
- **Artifacts installed outside the repo**: two surface classes write into
  files agrep does not own: taught blocks, and compaction integrations that
  point a resumed agent at `agrep postcompact` (`py/hookinstall.py`: Claude
  `PreCompact`, Codex compact-only `SessionStart`, and a shared pi/oh-my-pi
  extension). The pi-family extension also exports the exact live session ID
  and adds recovery instructions through the native compaction-summary context.
  Every artifact obeys preserve-and-disclose: a drifted artifact is reported,
  never repaired by a background snapshot-and-replace, because that pattern
  erases an edit made between the snapshot and the write. A taught block is
  versioned by its marker; hook and extension ownership is decided by hashing
  installed bytes against payloads agrep has shipped. A match may be upgraded;
  anything else is the user's and is left alone. A pre-existing integration is
  never displaced, removal takes out only agrep-owned entries, and an
  unparseable settings file or unreadable extension root is treated as the
  user's. Pinned in `py/test_teach_safety.py`, `py/test_hookinstall.py`, and the
  executable lifecycle contract in `py/test_pi_omp_extension.py`.
- **Test worlds**: `test_*.py` are hermetic units; `selftest.py` is the
  installed-reality gate (real binary, daemons, HOME, generated-surface
  pins). Every contract belongs to exactly one world; selftest stays one
  flat zero-fan-in file by design. If its wall-clock ever bottlenecks
  commits, parallelize the runner's schedule rather than splitting the file.

## `common.py` and its owners

`common.py` was decomposed into single-purpose owners and is now a 470-line
facade: `proc`, `events`, `resources`, `dist`, `console`, `settings`,
`session_context` (session publication and caller identity), `embedding_store`
(embedding identity, publication, legacy matrix IO, message loading),
`embedding_segments`, the `fileops` leaf (the atomic-replace primitive),
`index_lock` (the Rust-shared lock and its byte parser), `removal_fence`, and
`legacy_cleanup`. The facade keeps plain re-export blocks so older importers
work unchanged, while consumers of the new owners import them directly.

`py/test_common_facade.py` pins the exact owned-definition set, per-definition
executable lines, allowed assignments, total executable lines, and statement
count. Every row is an equality rather than a ceiling: any change to owned
logic must move that budget in the same commit, and unlisted definitions and
stale budget rows both fail. The facade currently carries nine owned
definitions, 187 owned executable lines, and 148 statements.

## Known exceptions

- `recall.main` stays large. Its apparent duplication with search encodes
  different contracts (prose-before-tools, probe semantics, multi-query
  diversity), pinned by parity tests.
- The `recall→search` upward edge stays. Recall uses 16 search symbols at 28
  sites; a query-engine extraction closes over 77 definitions and constants
  spanning 2,469 lines, and with 93 monkeypatch sites and 151 private-symbol
  references around that seam, a facade or callback would hide the dependency
  rather than remove it. Changing this means a narrower public query-engine
  interface with its own parity suite; until then the one-row allowlist
  describes the real architecture.
- `IndexLock` is a Rust-shared byte protocol rather than a Python-only
  ownerfile adopter, and it carries the highest corruption blast radius.
- `py/archive.py` maintains its own store-glob table (see adapter truth above).
- The resident build identity covers every shipped module, so warm daemons
  retire once on source movement by design.
- Candidate provenance separates content from lifecycle identity: distribution
  covers shipped Python/browser bytes, native is the SHA-256 prefix of the Rust
  binary, runtime binds daemon bytes to its interpreter, and writer binds that
  runtime to the native writer for mutation ownership.

## This document is pinned

`py/test_architecture_doc.py` resolves every backticked file reference in
this document against the tree, so a named file that does not exist fails the
suite. That does not make the prose true, but it makes the fabricated-
reference class of drift (naming tests or modules that were never written)
a test failure instead of an audit finding.
